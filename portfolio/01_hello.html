Project Hello Quad

3D Graphics

Project Overview

Hello Quad is the first assignment in CS250 Computer Graphics II at DigiPen Institute of Technology. The goal was to build the foundational OpenGL rendering pipeline from scratch and display an animated, textured quad on screen. This project covers the full lifecycle of GPU resource management — from allocating vertex and index buffers on the GPU, to uploading texture data, to configuring vertex attribute layouts and drawing indexed primitives.

Tasks Completed

  • Implemented the vertex buffer system to allocate GPU memory for geometry data and support dynamic partial data updates without reallocating the entire buffer.
  • Implemented the index buffer system to store triangle topology on the GPU, supporting multiple index precision widths to balance memory usage against maximum mesh size.
  • Implemented the texture loading system to decode image files and upload pixel data to the GPU with configurable filtering and wrapping behavior per texture coordinate axis.
  • Implemented the vertex array object system to describe the memory layout of each vertex attribute and bind index data to the draw call, encapsulating the full draw state in a single object.
  • Authored vertex and fragment shaders with time-based animation — vertex positions are displaced by a periodic wave and the fragment color blends smoothly between vertex color and texture color over time.

Reflection

Challenges

The most subtle difficulty was correctly implementing the relationship between the vertex array object and the index buffer. In OpenGL, the index buffer binding is stored as part of the vertex array object's state — so releasing the index buffer while the vertex array object is still bound silently severs the association. This produces no error message but causes nothing to be drawn, making the root cause extremely difficult to diagnose without knowing the ownership model in advance.

Solutions

The fix requires strict attention to unbind order: the vertex array object must be unbound before the index buffer is released, so the association is preserved in the vertex array object's state. Making this order explicit and consistent across the implementation prevents the silent failure entirely. Routing all OpenGL calls through a wrapper that logs errors after every call also helped surface problems during development that would otherwise have produced no output.

Learnings

OpenGL's binding model means that object state is recorded implicitly at the time of binding, not at the time of draw. Resources that appear independent can have hidden ownership relationships that only manifest as missing output rather than a reported error. Recognizing these implicit state dependencies — and encoding the correct operation order into the API design — is more reliable than relying on runtime diagnostics alone.
